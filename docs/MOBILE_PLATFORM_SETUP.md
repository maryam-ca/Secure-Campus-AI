# Mobile Platform Setup (Android/iOS native permissions)

`mobile/` currently contains only the Dart/Flutter application source
(`lib/`, `pubspec.yaml`, `analysis_options.yaml`) plus a real
`google-services.json` and a real (Android-only so far)
`lib/firebase_options.dart` for Firebase project **campus-a4087** — but
**not** the native `android/` and `ios/` platform folders themselves.
Those are generated by the Flutter tool, which isn't available in the
environment this project was built in. This is a required, one-time
step before the app will run anywhere.

## 0. IMPORTANT — package name must match exactly

The uploaded `google-services.json` registers Android package name
**`com.example.securecampus`**. When you generate the platform folders
(step 1), you MUST pass `--org com.example` so Flutter produces that
exact `applicationId` — otherwise the Google Services Gradle plugin
will fail at build time with *"No matching client found for package
name"*, because Firebase ties `google-services.json` to one specific
package name.

## 1. Generate the platform folders

From `mobile/`:

```
flutter create --org com.example --platforms=android,ios,web .
```

Run on an existing project like this, it adds the missing `android/`,
`ios/`, and `web/` folders without touching your existing `lib/`,
`pubspec.yaml`, or `analysis_options.yaml`.

## 2. Place google-services.json

Move the file that's currently at `mobile/google-services.json` into
its real required location:

```
mv google-services.json android/app/google-services.json
```

(`flutter create` does not do this for you — Firebase's own tooling
expects it at that exact path.)

## 3. Finish Firebase config for Web (and iOS, if you need it)

`lib/firebase_options.dart` already has **real, working Android
config** extracted from your uploaded file — Android should work as
soon as steps 1-2 are done and a device/emulator is available.

**Chrome/Web needs its own separate registration** — Android config
cannot be reused for Web (different SDK, different required fields
like `authDomain`). Fastest path, in order of preference:

**Option A — let FlutterFire do everything at once (recommended):**
```
dart pub global activate flutterfire_cli
flutterfire configure
```
This detects your `campus-a4087` project, lets you pick/create a Web
app (and iOS, if wanted) interactively, and safely overwrites
`lib/firebase_options.dart` with a complete, correct file for every
platform you select.

**Option B — manual, if you'd rather not install the CLI right now:**
1. Firebase Console → gear icon → *Project settings* → scroll to
   "Your apps" → **Add app** → the `</>` Web icon.
2. Register it (any nickname, e.g. "securecampus-web"), **skip** the
   hosting step.
3. Copy the `firebaseConfig` object it shows you.
4. Paste those values into the commented-out `web` block at the bottom
   of `lib/firebase_options.dart` and uncomment it, add `authDomain:`
   (shown in that same config), and add a `case TargetPlatform.web` /
   `if (kIsWeb) return web;` branch in `currentPlatform` in place of
   the current `throw UnsupportedError(...)` for web.

Until either is done, `flutter run -d chrome` will fail immediately
with a clear, specific error message (not a silent/generic one) telling
you exactly this.

## 4. Add the permissions these features need

Four features touch real device hardware and need explicit permission
declarations that `flutter create` does not add for you:

| Feature | Permission needed |
|---|---|
| Driver GPS sharing (`geolocator`) | Location |
| Librarian QR scanning (`mobile_scanner`) | Camera |
| Admin iris-enrollment photo capture (`image_picker`) | Camera, Photo library |
| Push notifications (`firebase_messaging`) | Notifications (iOS explicit; Android 13+ explicit, earlier implicit) |

### Android — `android/app/src/main/AndroidManifest.xml`

Add inside `<manifest>`, before `<application>`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

### iOS — `ios/Runner/Info.plist`

Add inside the top-level `<dict>`:

```xml
<key>NSCameraUsageDescription</key>
<string>SecureCampus needs camera access to scan library QR codes and capture iris-enrollment photos.</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>SecureCampus needs photo library access to select an iris-enrollment photo.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>SecureCampus needs your location so the Driver portal can share live bus location with Admin.</string>
```

## 5. Minimum SDK versions

`geolocator`, `mobile_scanner`, `google_maps_flutter`, and current
`firebase_*` packages generally require:
- Android `minSdkVersion 21` or higher (check `android/app/build.gradle`
  after `flutter create` — recent Flutter versions already default to
  21+, but confirm rather than assume). `google_maps_flutter` currently
  needs `compileSdk 36` — verified current for Flutter 3.47.x as of
  Sept 2026 (see docs/VERSION_AUDIT.md).
- iOS deployment target 13.0 or higher (`ios/Podfile` /
  `ios/Runner.xcodeproj`)

## 6. Google Maps API key (Admin's live bus map)

The Admin portal's live bus map (`google_maps_flutter`) needs a Google
Maps API key configured natively — this is separate from `MAP_API_KEY`
in `.env` (that one is for the optional server-side routing-ETA call in
`bus_eta/`; this one is for rendering the map tiles on-device) and
cannot be set through Dart code alone.

1. Create/enable a "Maps SDK for Android" and "Maps SDK for iOS" API key
   in the Google Cloud Console for your Firebase project.
2. **Android** — `android/app/src/main/AndroidManifest.xml`, inside
   `<application>`:
   ```xml
   <meta-data
       android:name="com.google.android.geo.API_KEY"
       android:value="YOUR_ANDROID_MAPS_API_KEY" />
   ```
3. **iOS** — `ios/Runner/AppDelegate.swift`, before `return super.application(...)`:
   ```swift
   import GoogleMaps
   GMSServices.provideAPIKey("YOUR_IOS_MAPS_API_KEY")
   ```
4. Restrict both keys (by package name/bundle ID and SHA-1 fingerprint
   for Android) in the Cloud Console before shipping anywhere beyond
   your own device.

## 7. After this

```
flutter pub get
flutter run -d android    # should work now with the real Android config
flutter run -d chrome     # needs step 3 (Web config) done first
```
